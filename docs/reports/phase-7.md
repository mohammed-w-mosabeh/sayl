# Phase 7 — Packaging

**Result:** a `.deb` and an AppImage that carry their own Python, a systemd user unit that
`sayl service` manages, staged yt-dlp updates, and a bilingual README with a user guide. CI
builds both bundles on Ubuntu 22.04, checks what is inside, and installs and exercises them on
clean systems. Publishing a GitHub release is left as a manual step.

## Decisions

| Decision | Why |
|---|---|
| Bundle a python-build-standalone CPython 3.12 in `/usr/lib/sayl/runtime`, not PyInstaller | `requires-python` excludes the 3.13 of Debian 13. Loose site-packages let a staged yt-dlp take precedence on `sys.path`, which a frozen build would shadow. mitmproxy and cryptography need no freezing hooks |
| Install from `uv export --frozen` with `--require-hashes` | The bundle runs exactly the tested lock, verified |
| Strip dependency test suites, Tk, `_tkinter`, IDLE; precompile with unchecked-hash pycs | `/usr` is read-only. tornado's tests held a private key. `_tkinter` broke linuxdeploy. The build now refuses any unresolved shared library |
| Build on Ubuntu 22.04 | The Tauri binary sets the glibc floor; 2.35 covers Ubuntu 22.04 and Debian 12 |
| The unit is generated by `sayl service install` and also shipped by the .deb | An AppImage has no fixed `ExecStart`. A moved AppImage is repaired on the next launch |
| `graphical-session.target`, `KillMode=mixed`, `TimeoutStopSec=30` | Starts after GNOME/KDE export the display variables. sayld stops aria2c and sayl-capture itself and restores the system proxy first |
| The shell runs the bundled `sayl service install` only when the port is closed | First launch sets sayld up for every login; a sayld started by hand is never fought |
| `Sayl.AppImage sayl …` and `sayld` dispatch in Rust before Tauri starts | One file gives the window, the CLI, and the daemon |
| yt-dlp updates apply at the next start, not hot-reloaded | yt-dlp imports lazily. Swapping modules under running downloads would mix versions |
| Updates are checked against PyPI's SHA-256 and import-tested in a child process before `current` changes | A bad or truncated wheel never becomes active. A staged copy that fails at startup falls back to the bundled one |
| The pinned `yt-dlp-ejs` is staged with yt-dlp | yt-dlp pins it exactly (`extra == "pin"`); YouTube needs the pair |
| Identifier `io.github.mohammed-w-mosabeh.sayl` | The old `io.github.sayl.desktop` named someone else's namespace. Tauri rejects underscores |
| The user guide is English only | CLAUDE.md allows Arabic only in the UI strings and the README |

## Bugs found by packaging

- `python -m cli.main` did nothing: the module had no `__main__` guard. The build check now
  requires the help text.
- An AppImage's AppRun sets `PYTHONHOME`, which broke sayl-capture's interpreter. Both the Rust
  dispatch and `daemon.launch` clear it, and the dispatch drops every other entry AppRun points
  into the AppImage (`PATH`, `LD_LIBRARY_PATH`, `XDG_DATA_DIRS`, ...).
- On first launch the window stayed on "sayld has never run here" until Retry. It now checks
  for the token every 2 s.

## Known limitations

- **The AppImage needs desktop graphics libraries** (`libEGL`) even for `sayl` commands,
  because the dispatch lives in the window's binary. The .deb has no such need.
- **Size.** The .deb is 121 MB (352 MB installed) and the AppImage 156 MB, because each
  carries its own Python and its dependencies.
- **A staged yt-dlp waits for a restart** of sayld (`sayl service restart`, or the next login).
- **Compositors without `graphical-session.target`** (sway and other wlroots compositors)
  need the two lines from the README.
- **The desktop app has no Capture switch**; capture is set up with `sayl capture`.
- **No GitHub release is published automatically.** Tag pushes build the bundles as workflow
  artifacts; creating the release is a manual step.
